How this works, and what it costs

A GitHub Action runs twice a day, calls six public feeds, drops rows that are not really a job, removes duplicates syndicated across boards, tags each listing with a field, and commits the result. The page you are reading is static — it loads one JSON file. No API key, no server, no scraping. Everything is in the open: the fetcher, the schedule, the data.

Read this before you spend an evening applying

A listing here is not a guarantee it is still open. This mirrors other people's boards twice a day; a role can be filled an hour after it is posted. The date shown is when the source published it, not when I checked it.

The field tag is a regex over the title, not a judgement. Each listing gets one field from the first rule its title matches, falling back to the source's own tags. It gets things wrong: an "Audio Engineer" lands in software because the word engineer is in the software rule. I use the title first precisely because board tagging is worse — one board filed "Pharmacy Technician Refill Calls" under an AI track. If a field looks thin, search instead of filtering.

Most listings say nothing about visa sponsorship. Only one source publishes that field at all, and on most of its rows it is blank. Blank means unstated, never "yes". Use the Says it sponsors filter to see only the ones that actually answered, and Hide no-sponsorship to drop the ones that have already ruled you out.

Want a verdict on whether a specific posting is worth your time rather than a list? That is the agent — it reads a posting against a CV and returns apply, caveat or skip. It needs an API key, so it runs on your own machine.
