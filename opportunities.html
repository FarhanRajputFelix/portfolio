How this works, and what it costs

A GitHub Action runs twice a day, calls eight public feeds, drops rows that are not really an opening, removes duplicates syndicated across boards, tags each listing with a type and a field, and commits the result. Rare categories get a quota so 500 ordinary jobs cannot bury 50 PhD places. The page you are reading is static — it loads two JSON files. No API key, no server, no scraping. Everything is in the open: the fetcher, the schedule, the data.

Read this before you spend an evening applying

A listing here is not a guarantee it is still open. This mirrors other people's boards twice a day; a role can be filled an hour after it is posted. The date shown is when the source published it, not when I checked it.

The field tag is a regex over the title, not a judgement. Each listing gets one field from the first rule its title matches, falling back to the source's own tags. It gets things wrong: an "Audio Engineer" lands in software because the word engineer is in the software rule. I use the title first precisely because board tagging is worse — one board filed "Pharmacy Technician Refill Calls" under an AI track. If a field looks thin, search instead of filtering.

The matcher checks stated requirements, and only those. It reads the profile you filled in against what each posting actually says. A green tick means nothing stated here rules you out — deliberately not "you qualify". Postings are silent about far more than they state, and a tool that turns silence into permission would send you to apply for things you cannot get. Only an explicit, quoted requirement can produce a red cross, which is why most crosses come from the hand-verified rows: those are the ones where somebody read the page.

Your profile never leaves this browser. It is held in localStorage and there is no server here to send it to. The GPA question asks for a band rather than a number, and the band is only ever compared against a stated minimum — the same trade the agent makes, where a tool returns PASS or FAIL and the figure itself never reaches the model. Clearing it removes it.

Scholarships are the weak spot, and here is why. Job boards publish APIs; scholarship providers publish web pages. ETH, KAUST, DAAD and the rest have no feed to read, so nothing can poll them. What you see is the honest split: research posts, PhD places and fellowships come live from jobRxiv and Nature Careers, which do publish feeds, while a small set of major funded programmes is checked by hand and marked verified. Those carry the quote and the date I read it. A daily job re-checks their links, but a working link is not a current deadline.

Most listings say nothing about visa sponsorship. Only one source publishes that field at all, and on most of its rows it is blank. Blank means unstated, never "yes". Use the Says it sponsors filter to see only the ones that actually answered, and Hide no-sponsorship to drop the ones that have already ruled you out.

Want a verdict on whether a specific posting is worth your time rather than a list? That is the agent — it reads a posting against a CV and returns apply, caveat or skip. It needs an API key, so it runs on your own machine.
