Explain it like you built it · Week 6

Why my link checker has an if target not in seen line

One line, in tools/check-links.py. I picked it because I genuinely didn't understand it. When I was told my homepage "didn't link to a single other page", my first thought was that the navigation must be broken — it wasn't. Every link worked; they were all anchors pointing at the same page. Six pages were live and returning 200 with no route to them from the homepage.

I thought this line was just there to avoid errors. It's not — it's the whole reason the code works at all.

Here's what I misunderstood: I assumed "checking if I've seen something" and "checking if something exists" were the same operation. They're not. A page can exist on disk and still never be seen by the walk, because "seen" only means one thing here: something already found a path to it.

The way I finally got it was thinking about it like retracing your steps in a maze. You don't re-walk a hallway you've already marked with chalk — not because the hallway disappeared, but because you already know where it leads. Without marking it, you'd walk the same loop forever. The seen set is the chalk.

What clicked for me: I kept asking "why does it need a list of visited pages, why not just check each page as I hit it?" The answer is that pages link to each other in circles. Page A links to B, B links back to A. Without memory of where you've been, you'd bounce between them infinitely and never finish. The moment I traced that loop on paper myself, it stopped being abstract.

If I were explaining this to someone building their first site: don't trust that a thing "exists" means a visitor can find it. Existing and being reachable are two different claims, and most bugs like this hide in that gap.
